# 批量制作

先完成一套中的代表动作，再扩展其余动作。新主题也先做样板，复用工具和制作方法，不复用其他顾客的角色特征。

## 文件组织

```text
<production-root>/<order-ref>/<skin-id>/
  design-brief.md
  batch-plan.json
  prompts.md
  images/                         定稿、原图
  actions/<action-id>/
    images/                       本段选用原图
    plan.json
    notes.md                      制作与修改说明
    visual-review.json            GIF 播放记录
    runs/<revision>/
      images/                     定位后的 PNG 帧
      gifs/                       GIF 成片
      qa/                         浅深底预览
      plan.json
      report.json
<delivery-root>/<skin-id>/         独立的交付目录
```

个人制作可省略订单层。顾客目录使用订单代号，选择不公开、不自动同步到远程的位置。动作原图放在本段 images 内，便于整段归档与重做。已有正确素材不为目录整齐而重复生成。

## 安排批次

用 [批次模板](../assets/batch-plan.json) 记录主题、动作、当前版本和下一步。示例名称、动作和尺寸按订单替换，未决定的参数留空。一个动作沿制作顺序完成，无依赖动作可分批处理；是否并行调用或委派由当前环境与用户授权决定。

GIF 接入任务依次使用这些状态：

| 状态 | 制作进度 |
| --- | --- |
| planned | 角色与动作已安排 |
| generated | 原图已保存 |
| alpha_checked | 透明区域、轮廓和道具已看过 |
| compiled | PNG 帧与 GIF 已导出 |
| integrated | 已装入目标软件并可显示 |
| verified | 本版本的播放与互动已完成检查 |

静态 PNG 跳过 GIF 编译和播放记录，查看尺寸、轮廓、透明区域及实际大小效果即可。只交付 GIF 时完成编译与预览后交付，运行状态留空。完整软件包再进行 [软件接入](integration.md)。

## 分段修改

- 身份或装扮不对：带上角色定稿，只修相关帧。
- 接触或转向不顺：回到关键姿势，补相邻区间。
- 裁切、定位或编码不对：修改帧计划，不重生正确原图。
- 共享定稿变了：检查使用它的动作和切换。
- 每次导出使用新 revision；保留上一个可用版本，处理问题后继续该段。

在 prompts.md 保存实际工具、完整提示词、选用参考与输出文件。编译器会保存参数和文件指纹，恢复制作时先用 verify_action.py 检查版本。原图、帧序或时长修改后重新导出并播放。

同一段的独立姿势、编码帧和整套表演数量分别统计。成套预览重点看待机→互动→待机，以及软件实际支持的休息、唤醒与中断切换。

## 整理交付

将选定 PNG 和 GIF 复制到交付目录的不同子目录，保持文件名与软件引用一致。制作记录、预览拼图和未选用版本留在制作目录。交付说明写清文件、版本、适用软件和已完成内容；源素材单独打包时按顾客约定处理。
