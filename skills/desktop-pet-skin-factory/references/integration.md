# 软件接入

根据目标软件现有的皮肤格式和加载方式接入，优先调整资源与配置。只有确实需要新增通用能力时才修改共享代码。

## 找到接入方式

查看项目说明、加载器和现有皮肤，确定：

- 皮肤描述文件、动作清单、缩略图与素材引用格式。
- 用户导入目录和内置资源目录。
- 单次、循环、保持末帧、退出回待机等播放方式。
- 状态、点击、右键菜单与动作的映射。
- 实际显示尺寸、透明命中区和减少动态设置。

制作 GIF 内的飞行或游动，不等于软件已经支持新的窗口运动方式。内嵌道具属于画面；独立点击需要软件本身的道具支持。

顾客私有皮肤使用私有交付包、用户导入目录或隔离测试副本。只有获准内置分发的皮肤才修改公共资源和构建复制配置。

## DesktopCat 格式

附带 check_skin.py 支持下面的资源布局：

```text
<skin-id>/
  skin.json
  manifest.json
  assets/images/
  assets/gifs/
```

skin.json 的 manifest 指向包内描述文件，两份文件有相同的非空字符串 id；素材使用 `file:assets/images/...` 或 `file:assets/gifs/...`。动作与行为字段以实际加载器为准，工具检查不替代完整的运行时格式定义。

```text
python <skill-dir>/scripts/check_skin.py <skin-root> --min-poses 2 --padding 4 --canvas 512 512
```

以上是命令示例，参数按作品设置。min-poses 检查每个 GIF 的不同像素帧数，不代表独立姿势数量；canvas 只检查 GIF，PNG 尺寸另行核对。参数对本次指定的包生效。

输出列出缺失引用、错误目录、无法解码、透明和边缘问题。返回码 0 表示文件检查通过，1 表示需要修改，2 表示参数或依赖问题。其他软件使用其自己的格式与检查方式。

## 播放与互动

用隔离配置试用，避免修改用户正在使用的宠物、尺寸和账号设置。确认皮肤发现、选择、缩略图、菜单与主要互动。

重点查看：

- 常态到动作、动作到待机的尺寸和位置。
- 单次动作的最后一帧时长，以及循环和保持末帧。
- 快速切换或重复触发后，旧回调不会抢回播放。
- 休息的进入、保持和唤醒是否完整。
- 追随、拖拽、聊天和菜单是否按软件规则互相协调。
- 道具延迟出现、点击、结束清理和屏幕边界。
- 减少动态设置下仍能完成必要交互。

Qt 项目分别试 QMovie 和静态 QPixmap；测试环境需要 GIF 解码插件，offscreen 模式还需要对应平台插件。保留透明命中区缓存，避免每帧重建完整窗口 mask。

使用现有测试并运行目标播放器。只交付素材时说明未接入软件；应用已适配的结论以实际运行结果为准。
