# 迷你聊天 UI 重设计

## 目标

把当前已经跑通的迷你聊天原型，整理成更像正式 Qt 桌面应用的交互。

这次设计同时覆盖迷你态和展开态。迷你态是一个轻量、可拖动的桌面输入条；展开态是同一套聊天组件展开后的完整聊天窗，而不是另一套旧 UI。桌宠回复气泡要像干净的漫画气泡，并且能根据桌宠在屏幕上的位置自动避开屏幕边缘。

## 范围

本次包含：

- 迷你态输入条的视觉和交互重设计。
- 展开态聊天窗与迷你态统一视觉风格。
- 迷你态和展开态复用同一套输入组件行为。
- 漫画气泡形状、hover 控制按钮、四方向避边布局。
- 空输入、少量输入、大量输入、等待回复等输入状态。
- 回复气泡跟随正在流式输出的桌宠回复，并在输出结束后按文本长度停留。

本次不包含：

- 改动 `ChatController` 的流式链路。
- 改动 SSE 解析、`ChatTextPacer`、sidecar API、模型 Provider 逻辑。
- 改动会话持久化策略。
- 引入新的图标素材依赖。

## 设计原则

- 桌面优先：这是 Qt 桌面浮窗，不按 Web 组件来设计。
- 迷你态默认一行：空输入和少量输入都保持单行，只有大量输入才增高。
- 输入条位置由用户控制：迷你输入条可拖动，并独立保存位置。
- 气泡位置由桌宠控制：回复气泡跟随桌宠，并负责避开屏幕边缘。
- 视觉噪音低：展开、关闭等控制用轻量文字图标，不做厚重方形按钮。
- 风格统一：迷你态和展开态使用同一套输入框、发送/停止按钮、圆角和描边语言。

## 迷你态

迷你态是一个浮动输入条，不是底部 dock，也不吸附到桌宠。

默认几何：

- 默认宽度约 `500-560px`，不要铺满屏幕。
- 单行外壳高度约 `72px`，内部输入框高度约 `50px`。
- 大量输入时，输入框随内容增高，到上限后内部滚动。
- 整个迷你输入条可以被用户拖动。
- 用户拖动后的位置独立保存，不跟桌宠位置混在一起。

布局：

```text
[展开图标] [ 内部带发送/停止按钮的输入框 ] [关闭图标]
```

控制：

- 展开图标在输入框左侧，使用轻量文字图标。
- 关闭图标在输入框右侧，使用轻量文字图标。
- 发送/停止按钮在输入框内部右下角。
- 空输入时发送按钮是浅色不可用态。
- 有输入时发送按钮变为可用态。
- 等待回复时，同一位置变为停止按钮。

行为：

- 空输入：单行输入框，显示 placeholder，发送不可用。
- 少量输入：仍保持单行，发送可用。
- 大量输入：输入框增高为多行，到最大高度后内部滚动。
- 等待回复：输入框回到单行等待态，右下角显示停止按钮。
- 关闭迷你聊天 UI 只隐藏聊天 UI，不取消正在进行的回复；桌宠回复和头顶气泡继续保留。

## 展开态

展开态沿用迷你态的视觉语言，只是把聊天记录和窗口控制展开出来。

窗口包含：

- 轻量标题栏：菜单/会话入口、标题、连接状态、收起、关闭。
- 聊天记录区。
- 与迷你态相同风格和行为的输入组件。

输入组件状态与迷你态一致：

- 空输入：单行，发送不可用。
- 少量输入：单行，发送可用。
- 大量输入：输入框增高，到上限后内部滚动。
- 等待回复：单行等待态，右下角显示停止按钮；聊天记录中同步流式显示回复。

展开态不是旧聊天工具栏的延续，而是迷你输入条展开后的完整聊天窗。

## 漫画回复气泡

回复气泡只显示桌宠，也就是 assistant/Miles 的回复。气泡内容继续以 `ChatController.messages` 为来源，复用现有流式节奏；展开态正在输出的那条回复，迷你态气泡也要用同样文字节奏显示。

视觉形状：

- 干净的漫画气泡。
- 白色填充，单层深色外描边。
- 不要内圈描边。
- 不要额外装饰线。
- 气泡主体和尖角必须是一条连续形状。
- 不要用单独的三角形或矩形拼接尖角，避免出现接缝或线条插入气泡内部。

实现倾向：

- 优先用 QML `Shape` 或 `Canvas` 画同一个闭合 path。
- 每个尖角方向对应一个 path。
- 如果用 `Canvas`，先填充白色，再画同一条连续外描边。

气泡控制：

- 展开和关闭都是文字图标，不是方形按钮。
- 默认隐藏。
- hover 气泡时两个图标一起出现。
- 两个图标使用同一种灰色和透明度。
- 图标固定在气泡主体右上角内侧，距离顶部和右侧约 `18-24px`。
- 图标位置不跟随尖角移动。
- 点击展开图标打开完整聊天窗。
- 点击关闭图标只隐藏当前气泡，不影响聊天 UI、流式回复或会话记录。

气泡停留：

- 回复流式输出期间，气泡持续显示。
- 回复结束后，根据最终文本长度停留一段时间再自动隐藏。
- 停留规则：基础停留 `2.5s`，每约 `20` 个中文字符增加 `1s`，最长不超过 `10s`。
- 如果用户 hover 气泡，暂停自动隐藏倒计时；移出后继续倒计时。

## 气泡避边布局

气泡跟随桌宠，不跟随迷你输入条。

迷你输入条由用户自由拖动，气泡布局不拿输入条位置做避让。如果用户把输入条拖到桌宠或气泡附近，应用只保证气泡不会跑出屏幕，不额外改动用户选择的输入条位置。

气泡支持四种相对桌宠的位置：

| 桌宠所在区域 | 气泡位置 | 尖角位置 |
| --- | --- | --- |
| 桌宠靠左上 | 气泡在桌宠右下 | 气泡左上尖角 |
| 桌宠靠右上 | 气泡在桌宠左下 | 气泡右上尖角 |
| 桌宠靠左下 | 气泡在桌宠右上 | 气泡左下尖角 |
| 桌宠靠右下 | 气泡在桌宠左上 | 气泡右下尖角 |

默认放置优先级：

1. 优先放在桌宠上方，并尽量水平居中。
2. 上方空间不足时，改到桌宠下方。
3. 右侧会越界时，改用左侧布局。
4. 左侧会越界时，改用右侧布局。
5. 最终气泡矩形 clamp 到桌宠所在屏幕的 `availableGeometry` 内。
6. clamp 后，尖角仍然尽量指向桌宠中心或可见身体中心。

## 状态矩阵

必做状态：

| 模式 | 状态 | 预期 UI |
| --- | --- | --- |
| 迷你态 | 空输入 | 单行输入框，placeholder，发送不可用 |
| 迷你态 | 少量输入 | 单行输入框，发送可用 |
| 迷你态 | 大量输入 | 多行输入框，发送可用，高度有上限 |
| 迷你态 | 等待回复 | 单行等待态，停止按钮，气泡流式显示回复 |
| 展开态 | 空输入 | 单行输入框，placeholder，发送不可用 |
| 展开态 | 少量输入 | 单行输入框，发送可用 |
| 展开态 | 大量输入 | 多行输入框，发送可用，高度有上限 |
| 展开态 | 等待回复 | 单行等待态，停止按钮，聊天记录流式显示回复 |

补充状态：

- Provider 未配置：保持同样几何，placeholder 提示需要配置，发送不可用。
- sidecar 未连接：保持同样几何，placeholder 提示需要重连，发送不可用。
- 用户请求停止：停止按钮在 controller 退出发送态后恢复为发送按钮；已接收文本继续沿用现有流式/节奏行为。

## Qt/QML 实现说明

- `ChatController` 继续作为聊天状态唯一来源。
- 不改动流式、节奏控制和消息持久化。
- 如果能减少重复，可以抽出可复用的 QML 输入组件。
- 输入条和输入框使用稳定宽高、最大高度，避免状态切换时跳动。
- 使用 `TextArea` 内容高度驱动输入框高度，并按模式设置最大高度。
- 纯图标控制需要保留 tooltip。
- 气泡位置用桌宠几何、气泡尺寸、桌宠所在屏幕 `availableGeometry` 计算。
- 气泡形状和尖角方向由同一个 placement 结果驱动，避免视觉和布局状态不一致。

## 验收标准

- 迷你态空输入和少量输入保持一行。
- 迷你态大量输入会增高，到上限后内部滚动。
- 展开态使用同一套输入组件视觉和状态行为。
- 发送/停止按钮在输入框内部右下角。
- 迷你输入条可拖动，且不跟桌宠位置绑定。
- 回复气泡是一条干净连续的漫画气泡轮廓，没有内部接缝。
- hover 气泡时出现同色的展开/关闭文字图标。
- 气泡能在桌宠四个屏幕边角附近正确换向，并保持在屏幕 `availableGeometry` 内。
- 气泡流式节奏与展开态当前 assistant 回复一致。
- 回复结束后，气泡按文本长度停留后自动隐藏，hover 时不会突然消失。
- 现有聊天流式相关测试继续通过。
