# 迷你聊天 UI 二次打磨设计

## 目标

在已经跑通的迷你聊天基础上，修正这轮视觉和交互问题，让迷你态、展开态和桌宠回复气泡看起来像同一套正式桌面 UI。

这轮重点不是改聊天链路，而是把 UI 打磨到可用：

- 迷你态去掉外层系统窗口感，只保留一个可拖动的圆角输入条。
- 展开态重做为同一套视觉语言的完整聊天窗。
- 回复气泡只在迷你态或聊天 UI 隐藏时显示，展开态不显示。
- 回复气泡基于桌宠可见像素定位，而不是透明窗口矩形。
- 气泡更贴近桌宠，位置更居中，容量更合理。
- 图标统一使用清晰的线性 SVG 图标。

## 范围

包含：

- 迷你态输入条视觉和拖动区域调整。
- 展开态聊天窗视觉重做。
- 输入组件在迷你态和展开态继续复用。
- Lucide 线性 SVG 图标落地为本地资源。
- 桌宠可见像素边界计算，用于气泡定位。
- 气泡尺寸、距离、文本容量和避边策略调整。
- 相关 QML/C++ 合同检查和 smoke tests。

不包含：

- 修改 `ChatController` 流式输出链路。
- 修改 `ChatTextPacer` 字符节奏。
- 修改 sidecar、Provider、SSE 解析或会话持久化。
- 改动 Phase 2.4 动画链逻辑。
- 引入运行时图标库依赖；图标只作为本地 SVG 资源使用。

## 已确认设计决策

### 图标

图标使用 Lucide 的线性 SVG，本地化到桌面资源中，保持 `fill="none"`、`stroke="currentColor"` 语义，不手写或重组 path。

确认组合：

| 用途 | 图标 |
| --- | --- |
| 设置 | `settings` |
| 重连 | `refresh-ccw` |
| 展开 | `maximize-2` |
| 收起 | `minimize-2` |
| 关闭 | `x` |
| 菜单/会话入口 | `menu` |

展开和收起必须成对：迷你态用 `maximize-2`，展开态用 `minimize-2`。不要再用下拉箭头、准星或类似撤销的图标表达这些操作。

### 颜色和按钮形态

- 顶栏和气泡内的小图标都是线性图标，不做厚重方形按钮。
- 默认颜色使用低对比灰色。
- hover 后可以提高透明度或加轻微背景，但不能出现明显的实心方块。
- 气泡右上角的展开和关闭按钮颜色、尺寸、透明度必须一致。

## 迷你态输入条

迷你态不再显示外层系统窗口或大白色外框。屏幕上只应看到一个圆角输入条本体。

默认尺寸：

- 默认宽度约 `380px`。
- 可按内容和平台字体微调到 `360-420px`。
- 单行高度约 `52-58px`。
- 大量输入时高度增长，上限约 `132-148px`，超过后输入框内部滚动。

布局：

```text
[展开图标] [ 输入区，发送/停止按钮在右下角 ] [关闭图标]
```

行为：

- 空输入和少量输入保持单行。
- 输入内容变多时才增长为多行。
- 发送按钮在输入框内部右下角，图标必须居中，不能歪斜。
- 等待回复时，发送按钮位置变为停止按钮。
- 关闭按钮只隐藏聊天 UI，不取消正在回复的内容，气泡继续显示。
- 展开按钮打开完整聊天窗，并隐藏当前气泡。

拖动：

- 迷你输入条可以由用户任意拖动。
- 凡是没有特殊交互的区域都可拖动整个输入条。
- 输入框文字编辑区域、发送/停止按钮、展开按钮、关闭按钮不能被拖动层拦截。
- 用户拖动位置独立保存，不和桌宠位置绑定。

## 展开态聊天窗

展开态要和迷你态使用同一套视觉语言，而不是旧聊天窗加一个输入框。

窗口形态：

- 使用自绘浅色圆角窗口，不显示系统标题栏那一圈外壳。
- 顶栏、聊天记录区、输入区在同一个干净容器内。
- 不给底部输入区额外套一圈大 border；输入框本体已经提供边界。

顶栏：

```text
[menu] Miles [连接状态]                    [settings] [refresh-ccw] [minimize-2] [x]
```

顶栏行为：

- `menu` 作为会话/菜单入口预留。
- `settings` 打开设置。
- `refresh-ccw` 表示重连或重新连接 sidecar/provider。
- `minimize-2` 收起为迷你态。
- `x` 隐藏聊天 UI。
- 顶栏空白区域可拖动窗口。

聊天记录区：

- 背景为温和浅色，不使用厚重面板或多层卡片。
- 用户消息靠右，assistant 消息靠左。
- 消息气泡保持轻描边和适度圆角。
- 正在流式输出的 assistant 回复只在聊天记录里显示；展开态不显示桌宠头顶气泡。

底部输入区：

- 使用和迷你态同一个 composer 组件。
- 空输入和少量输入保持单行。
- 大量输入时 composer 向上增长，到上限后内部滚动。
- 发送/停止按钮在输入框内部右下角，位置和迷你态一致。
- 输入区不能歪斜，按钮图标必须在按钮视觉中心。

## 回复气泡

气泡只属于迷你态体验。

显示规则：

- 迷你态显示桌宠回复气泡。
- 展开态不显示气泡。
- 聊天 UI 被关闭时，如果仍有正在输出或处于停留期的回复，气泡继续显示。
- 从迷你态展开时立即隐藏气泡。
- 从展开态收起时，如果当前 assistant 回复仍在输出或停留期内，可以重新显示气泡。

内容规则：

- 只显示 assistant/Miles 的回复。
- 复用 `ChatController.messages` 中已经按节奏输出的文本。
- 正在输出时，气泡和展开态聊天记录的文字节奏一致。
- 输出结束后按文本长度停留，再自动隐藏。

尺寸：

- 最大宽度从上一版收窄，目标约 `300-320px`。
- 最小高度只包住短文本，不强行撑大。
- 最大高度提高到约 `300-360px`。
- 达到高度上限后，优先保留最新文本可见；不要只显示两行就截断。

形状：

- 干净漫画气泡，白色填充，单层外描边。
- 没有内圈描边，没有装饰线。
- 主体和尖角必须是一条连续闭合路径。
- 不用单独三角形拼接尖角，避免接缝、线条交错或尖角插入气泡内部。

控制：

- 右上角显示 `maximize-2` 和 `x`。
- 默认隐藏，hover 气泡时同时出现。
- 两个图标同色、同尺寸、同透明度。
- 图标放在气泡主体右上角内侧，离边缘约 `14-18px`，不能贴边。
- 点击 `maximize-2` 展开完整聊天窗。
- 点击 `x` 只隐藏当前气泡，不影响回复、聊天 UI 或会话记录。

## 气泡定位

上一版气泡离桌宠太远，核心原因可能是使用了桌宠透明窗口矩形。用户看到的是 GIF 不透明像素，而不是透明窗口。

本轮定位基于桌宠可见像素边界：

- `PetSurfaceWindow` 或相邻 C++ 层从当前 `QMovie`/当前帧拿到 `QImage`。
- 扫描 alpha 像素，计算当前帧的不透明内容边界。
- 将帧内边界映射到桌宠窗口坐标，再映射到屏幕坐标。
- 对可见边界加少量 padding，避免贴得太紧。
- 如果当前帧不可用、完全透明或映射失败，回退到现有桌宠窗口矩形。

稳定性：

- 可见边界不能因为单帧动作抖动导致气泡乱跳。
- 可以缓存最近有效边界，或对边界变化做轻量平滑。
- 定位更新只需要跟随桌宠移动和可见边界显著变化，不要求每帧强制重排。

距离和对齐：

- 气泡和可见桌宠边界的间距约 `8-16px`。
- 气泡尽量靠近桌宠头顶或身体中心，不要过度偏左/偏右。
- 当屏幕边缘空间足够时，气泡主体优先相对可见边界中心对齐。
- 当靠近屏幕边缘时，允许偏移并 clamp 到 `availableGeometry` 内，但尖角仍尽量指向可见桌宠中心附近。

四向避边：

| 桌宠可见位置 | 气泡位置 | 尖角位置 |
| --- | --- | --- |
| 靠左上 | 右下 | 左上尖角 |
| 靠右上 | 左下 | 右上尖角 |
| 靠左下 | 右上 | 左下尖角 |
| 靠右下 | 左上 | 右下尖角 |

默认优先级：

1. 优先尝试放在桌宠可见边界上方。
2. 上方空间不足时放下方。
3. 水平方向优先让气泡中心接近桌宠可见中心。
4. 越界时向屏幕内侧移动。
5. 最终整体 clamp 到当前屏幕 `availableGeometry`。
6. clamp 后重新计算尖角锚点，让尖角尽量指向桌宠可见中心附近。

## 技术边界

- `ChatController` 继续是聊天状态唯一来源。
- QML 负责视觉状态和输入交互。
- C++ 负责可测试的几何计算：桌宠可见边界、气泡 placement、屏幕 clamp。
- 图标以 SVG 资源形式进入 Qt resource，不引入新的运行时依赖。
- 迷你态和展开态共享 composer，避免两套输入逻辑分叉。
- 气泡 Canvas/Shape 的 path 由 placement 的方向驱动，布局方向和尖角方向不能各算各的。

## 验收标准

- 迷你态屏幕上只看到圆角输入条，没有外层系统窗口或大外框。
- 迷你输入条默认比当前实现更小，空输入和少量输入保持单行。
- 迷你输入条非交互空白区域可拖动；输入、发送、展开、关闭仍可正常点击。
- 发送/停止按钮在输入框内部右下角，图标居中、不歪斜。
- 展开态是同一套浅色自绘聊天窗，不显示旧系统标题栏外壳。
- 展开态底部输入区没有多余外层 border。
- 顶栏图标使用确认的 Lucide 组合，线性渲染正常，不出现黑块填充。
- 气泡只在迷你态或聊天 UI 隐藏时显示，展开态不显示。
- 气泡基于桌宠可见像素边界定位，而不是透明窗口矩形。
- 气泡比当前实现更靠近桌宠，且不会过度偏左/偏右。
- 气泡最大宽度约 `300-320px`，最大高度约 `300-360px`，长回复能显示多行。
- 气泡主体和尖角是连续闭合路径，没有接缝或线条插入内部。
- 气泡 hover 控制图标同色同尺寸，位置不贴边。
- 桌宠在屏幕四角附近时，气泡能选择正确方向并保持在 `availableGeometry` 内。
- 现有聊天流式、节奏和会话相关测试继续通过。
