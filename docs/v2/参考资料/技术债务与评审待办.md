## README 同步的框架债务

来源：`README.md` 的“Phase 2 期间可以并行处理的框架债务”。这些项目不是 Phase 2.3.1 验收范围，但属于 v2 框架继续演进时容易遗忘的结构性工作。

### [Runtime/Skin] HitZone schema 迁到 image-space

当前 HitZone 已能支撑 v1 手感回归，但长期 schema 需要以资源图片坐标作为稳定基准，而不是依赖窗口缩放后的运行时坐标。

需要处理：

- 明确 manifest 中 HitZone 坐标的 canonical space。
- 给现有 Miles 皮肤提供迁移值或兼容加载路径。
- 更新 [HitZone 交互区域系统设计](../设计方案/HitZone%20交互区域系统设计.md) 与对应 contract / smoke test。

### [UX] 连续缩放控件

当前桌宠缩放能力仍偏向离散配置和旧版手感回归。后续需要补一个用户可直接操作的连续缩放控件，提升日常使用体验。

需要处理：

- 决定入口放在右键菜单、设置窗口还是独立开发者工具。
- 明确缩放值的保存位置、默认值和多屏边界重算规则。
- 验证缩放时 HitZone、alpha mask、Prop 跟随和移动边界同步更新。

### [Tooling] Pet Skin Studio

皮肤包已经有 manifest、素材盘点和运行时加载机制，但缺少面向皮肤作者的编辑 / 校验工具。Pet Skin Studio 用于降低皮肤包制作成本。

需要处理：

- manifest 编辑、预览和校验入口。
- HitZone、ActionPool、BehaviorRule、ExpressionMapping 的可视化编辑。
- 与 `skin:` URL、用户皮肤目录和内置皮肤覆盖规则保持一致。

### [Runtime] `PetRuntime` 内部继续拆分

`PetRuntime` 已开始拆分 manifest、候选池选择、behavior trigger、hit zone、皮肤命令和 Prop 状态管理，但 playback 与 recipe 主流程仍需要继续收口。

需要处理：

- 抽出 `PlaybackController`，集中管理当前动画、边界、clean finish、serial / generation 和安全超时。
- 抽出 `RecipeRunner`，集中管理 recipe step、onceThenIdle、facingAfter 和 pending request。
- 拆分时同步更新 [桌宠运行时职责拆分设计](../设计方案/桌宠运行时职责拆分设计.md) 和 runtime smoke tests。
