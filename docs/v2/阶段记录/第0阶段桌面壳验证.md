# Phase 0 Desktop Shell Verification

本文档记录 v2 Qt/QML desktop shell 在 Phase 0 阶段的构建、运行、手动检查项和当前限制。目标是确认桌宠窗口壳层已经具备基本桌面行为，为后续 Pet Runtime、聊天窗口和设置界面接入做准备。

## Build

### 前置工具

Phase 0 构建需要先安装 Xcode Command Line Tools、CMake、Ninja 和 Qt 6。当前验证环境是 Qt 6.11；工程基础要求保持在 Qt 6.5+，并对 Qt 6.8+ 的 QML policy 做了兼容处理。
桌宠右键菜单使用 `Qt.labs.platform Menu`，因此桌面端会链接 Qt Widgets 作为平台菜单兼容层。Apple Silicon Mac 通常使用 Homebrew 的 `/opt/homebrew` 前缀；Intel Mac 通常使用 `/usr/local` 前缀。

```sh
xcode-select --install
brew install cmake ninja qt
```

安装后可以用这些命令确认工具可用：

```sh
clang++ --version
cmake --version
ninja --version
qtpaths6 --version
```

### Apple Silicon

```sh
cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH=/opt/homebrew
cmake --build build
```

### Intel Mac

```sh
cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH=/usr/local
cmake --build build
```

## Run

```sh
open build/apps/desktop/MilesEdgeworthDesktop.app
```

## Automated Checks

窗口层级仍然需要真实 macOS 桌面环境手动验证，但仓库里保留了一个小的静态检查，
用来防止普通“始终置顶”开关重新依赖 SkyLight 私有 Space：

```sh
cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH=/opt/homebrew
cmake --build build
ctest --test-dir build --output-on-failure
/opt/homebrew/bin/qmllint -I build/apps/desktop apps/desktop/qml/PetWindow.qml
```

其中 `check_phase_0_5_pet_runtime` 会额外检查：

- QML 通过 `DesktopShell` 和 `PetRuntime` singleton 访问桌面壳层。
- `DesktopShell` 和 `PetRuntime` 已作为 QML singleton 暴露。
- `AnimatedImage` 的资源路径由 `PetRuntime.currentAnimationUrl` 驱动。
- 内置 skin manifest 至少包含 `idle`、`thinking`、`speaking` 三个状态。

`check_phase_0_6_animation_runtime` 会额外检查：

- 内置 skin manifest 已升级到 `schemaVersion: 2`。
- action 支持 `variants.right` / `variants.left`，可以按当前朝向选择资源。
- `PetRuntime` 暴露 `currentFacing`、`currentLoopMode`、`currentAutoReturnToIdle` 和 `playbackSerial`。
- QML 会在 `AnimatedImage` 到达最后一帧时通知 `PetRuntime.handleAnimationFinished()`。
- `docs/v2/参考资料/动画素材盘点.md` 已记录初始素材语义和待复核项。

`check_phase_0_7_phase_runtime` 会额外检查：

- 内置 skin manifest 已支持 `Action -> Phase -> Variant -> Clip` 的多阶段动作结构。
- `sleep` action 已拆成 `enter`、`loop`、`exit` 三个 phase，分别对应入睡、睡眠循环和醒来。
- `PetRuntime` 暴露 `currentPhaseId`，并提供 `playPhase()` 与 `testSleep()` 骨架。
- QML 菜单中已接入“测试睡觉”，并会让 `once` / `onceThenIdle` 阶段在播到末帧后回调运行时。

`check_phase_0_54_assets_layout` 会额外检查：

- Miles 皮肤资源已迁入 `apps/desktop/resources/skins/miles-edgeworth/assets/`。
- `pet_assets.qrc` 不再引用根目录 `gifs/`、`audios/` 或 `prosbadge.png`。
- `qrc:/pet/*` 和 `qrc:/audio/*` 的关键 alias 继续存在，避免运行时 URL 变化。

`check_phase_0_55_pet_runtime_manifest_split` 会额外检查：

- manifest 数据结构已移入 `SkinManifest.h`。
- `PetRuntime` 通过 `SkinManifest m_manifest` 持有皮肤配置，不再内联定义 schema struct。

`check_phase_0_56_pet_runtime_service_split` 会额外检查：

- `SkinManifestLoader` 接管 manifest JSON 解析和 fallback manifest。
- `ActionPoolSelector` 接管语言覆盖池与权重抽取。
- `BehaviorTriggerEngine` 接管 behavior trigger 条件匹配与权重抽取。

`check_phase_0_57_hit_zone_matcher` 会额外检查：

- `HitZoneMatcher` 接管单击区域坐标归一化、朝向区域选择和 rect / polygon 命中判断。
- `PetRuntime` 不再直接维护 hit zone helper，只保留 QML 单击入口和播放动作池的调度。
- 主程序和 `PetRuntimeSmoke` 都链接 `HitZoneMatcher`，避免测试路径和运行路径分叉。

## Manual Checks

手动验证时，先完成对应架构的 Build，再使用 Run 命令启动应用。启动后检查以下桌面壳层行为：

- 透明无边框：桌宠窗口背景应透明，窗口本身不显示系统标题栏、边框或默认窗口装饰。
- 拖拽：按住桌宠可移动窗口位置，松开后窗口停留在新的桌面坐标。
- 退出入口：右键桌宠应弹出平台菜单，点击“退出”后应用关闭。
- 菜单关闭：右键菜单打开后，点击菜单外部应能自动关闭菜单。
- 置顶开关：右键桌宠应能在“取消置顶”和“始终置顶”之间切换。
- 系统托盘：启动后系统托盘应出现 MilesEdgeworth 图标；右键托盘图标应能看到“退出”；单击托盘图标应能唤起桌宠窗口。
- 失焦后可见：点击其他应用让桌宠失焦后，桌宠仍应保持可见，不应因为失焦而隐藏或最小化。
- 切换 Spaces 可见：在 macOS Spaces 之间切换时，桌宠应继续出现在当前 Space 中。
- 全屏 app 上方可见：切到全屏应用后，桌宠应仍显示在全屏应用上方。
- 取消置顶后可覆盖：点击“取消置顶”后，桌宠仍不应因为应用失焦而隐藏，也不应主动沉到窗口栈底部；后续允许被其他窗口自然覆盖。重新点击“始终置顶”后，应恢复当前 Phase 0 的跨 Space / 全屏上方显示行为。
- 动画资源 alias：运行态确认 `qrc:/pet/stand-right.gif` 可以解析并显示。`stand-left` 已注册 alias，但 Phase 0 还没有切换朝向的运行时入口，后续由 Pet Runtime 验证。
- 启动入场位置：启动后桌宠应先出现在屏幕左下角略微越界的位置，再随 `briefcaseIn` / `briefcaseStop` 入场流程回到站立状态，保留旧版第一次出现时的“走进屏幕”手感。
- Phase 0.5 / 0.6 动作测试：右键菜单中的“回到待机”“切到朝左/朝右”“测试思考”“测试异议”“测试鞠躬”应能在站立、思考、异议/强调、鞠躬动画之间切换。
- 一次性动作回 idle：`objecting` 和 `bow` 的 `loopMode` 为 `onceThenIdle`，播到最后一帧后应自动回到当前朝向的站立动画。
- Phase 0.7 睡觉动作：右键“测试睡觉”后，应先播放入睡动作，再进入睡眠循环；睡眠时右键“回到待机”，应先播放醒来动作，再回到当前朝向的站立动画。
- Phase 0.7 睡眠朝向：睡眠循环中点击“切到朝左/朝右”时，应保持在睡眠 phase，并切换到对应朝向的睡眠资源。
- Phase 0.46 身体边界：走路、跑步和拖拽移动时，窗口边界应按旧版身体点位夹取，而不是按完整透明窗口外壳夹取；透明留白可以略微越界，角色主体仍留在屏幕内。
- Phase 0.47 双屏选项：右键菜单应恢复旧版“单屏 / 主屏幕在左侧 / 主屏幕在右侧”入口；双屏模式下移动边界横向使用虚拟桌面范围，允许自动走跑和拖拽跨过左右屏幕边界。
- Phase 0.48 手型光标：鼠标移入桌宠交互区域时应显示手型光标，保留旧版“可以点我 / 拖我”的轻提示。
- Phase 0.49 双击释放：连续两次左键点击时，第二次按下应取消第一次单击计时，第二次松手只触发双击动作，不应再排队一次单击分区反应。
- Phase 0.50 静音音量：右键勾选“静音”后，新的语音请求不会播放，正在播放的语音音量也应立即降为 0。
- Phase 0.52 idle 触发配置：站立动画播完一轮后，是否进入随机待机池由皮肤 manifest 的 `behaviorTriggers.idle.loopFinished` 决定。
- Phase 0.54 资源布局：运行资源应从皮肤包 `assets/` 加载，同时 `qrc:/pet` 和 `qrc:/audio` alias 保持稳定。
- Phase 0.55 / 0.56 运行时拆分：manifest 数据、JSON 加载、候选池选择和 behavior trigger 选择已经离开 `PetRuntime`；手动检查重点是旧版手感不能因拆分发生变化。
- Phase 0.57 命中区域拆分：单击脸部、头部、手臂、身体和腿部时，左右朝向、polygon 斜线区域和动作池选择应与拆分前一致。

## Known Limits

- Phase 0 点击区域仍是矩形，尚未按透明像素或角色轮廓裁剪命中区域。
- Phase 0 已接入平台右键菜单和系统托盘退出入口；后续仍需接入聊天窗口、设置中心和更完整的托盘菜单。
- Pet Runtime 已接入 state/action/phase/recipe/action pool、旧版随机 idle、移动、点击、双击、睡眠、喝茶、拖拽晃动和检察官徽章 Prop；完整动画编排器、动态 recipe 参数和插件化交互仍在后续阶段。
- 已注册 `stand`、`thinking`、`objecting`、`bow`、`tea`、walk/run 等核心资源；资源物理文件已迁入 Miles 皮肤包 `assets/`。8 方向移动已接入最小移动系统，路线规划和目标点移动还未实现。
- macOS 普通置顶开关使用标准 AppKit 窗口层级：置顶时切到 screen saver level 并加入所有 Space，取消置顶时降回普通窗口层级。这样比 SkyLight 私有 Space 更适合做可逆开关。
- SkyLight 私有 Space 暂不作为普通置顶开关的实现。它可以作为未来“固定在屏幕最上层”的实验模式单独设计，但需要接受私有 API、不稳定、退出时可能要重建窗口等代价。
- macOS 全屏 / Mission Control 场景仍需要真实机器手动验证。Qt 的 QWindow 与原生 NSPanel 行为不同；如果全屏覆盖能力不足，下一步应改用 macOS 专用 NSPanel 容器，普通置顶开关继续保持标准 AppKit 层级。
- Phase 0 暂时不使用 `Qt.Tool`。macOS 由 `NSApplicationActivationPolicyAccessory` 和原生窗口属性承担辅助应用行为；Windows/Linux 的任务栏隐藏策略后续再单独验证。
- Windows/Linux 桌面层级、透明窗口、跨工作区和全屏覆盖行为需要另行验证。

## Phase 0.44 系统托盘

Phase 0.44 恢复旧版常驻桌宠的系统托盘入口。旧版 `createTrayIcon()` 会创建托盘图标，右键菜单只保留退出入口，单击托盘图标会 `activateWindow()` 找回桌宠窗口。

v2 对应实现放在 `DesktopShellController`：

```text
DesktopShellController
  -> createTrayIcon()
  -> QSystemTrayIcon(":/icon/favicon-bar.ico")
  -> QMenu("退出")
  -> revealPetWindow()
```

当前策略：

- 应用启动后创建托盘图标，并使用旧版 `favicon_bar.ico` 作为托盘图标资源。
- 托盘右键菜单提供“退出”，触发 `QCoreApplication::quit()`，退出整个应用。
- 托盘单击调用 `revealPetWindow()`，对桌宠窗口执行 `show()`、`raise()` 和 `requestActivate()`。
- `main.cpp` 调用 `app.setQuitOnLastWindowClosed(false)`，避免后续隐藏窗口或关闭辅助窗口时误退出常驻应用。

后续托盘可以继续扩展“打开聊天”“打开设置”“暂停桌宠”等入口，但退出能力先保持和旧版一致。

## Phase 0.45 启动入场位置

旧版构造桌宠窗口时，会在播放 `briefcaseIn0.gif` 前把窗口移动到主屏幕左下角：

```cpp
move(desktopRect.x() - 45 * scale,
     desktopRect.y() + desktopRect.height() - 90 * scale);
```

这个位置不是完整窗口的屏幕内坐标，而是按角色身体的大致位置计算，让透明外壳可以略微越过屏幕边缘。随后旧版的 `BRIEFCASEIN` 动画会配合 `runMove()` 让 Miles 像是从屏幕外走进来。

v2 在 `DesktopShellController::placePetWindowForStartup()` 中保留这套启动定位。调用时使用 `PetRuntime.petScale()`，默认中号对应旧版 `scale = 2`。启动定位直接调用 `QWindow::setPosition()`，不会经过普通移动边界夹取；后续走路、跑步和拖拽仍然继续使用 `movePetWindowTo()` / `clampedPetWindowPosition()`，避免自动移动把桌宠带出屏幕。

## Phase 0.46 身体点位边界

旧版 `moveEvent()` 使用角色身体附近的四个点判断是否越界：

```cpp
QPoint topLeft = newPos + QPoint(36 * scale, 10 * scale);
QPoint topRight = newPos + QPoint(63 * scale, 10 * scale);
QPoint bottomLeft = newPos + QPoint(36 * scale, 90 * scale);
QPoint bottomRight = newPos + QPoint(63 * scale, 90 * scale);
```

窗口左上角坐标的限制范围对应为：

```text
xMin = screen.x - 36 * scale
xMax = screen.x + screen.width - 63 * scale
yMin = screen.y - 10 * scale
yMax = screen.y + screen.height - 90 * scale
```

Phase 0.46 将这组旧版常量迁入 `DesktopShellController::clampedPetWindowPosition()`。壳层通过 `setPetScale()` 接收 `PetRuntime.petScale()`，所以用户在右键菜单里切换迷你 / 小 / 中 / 大后，移动边界也会跟随当前 scale 更新。

当前身体边界仍是 Miles 官方皮肤的硬编码迁移结果。后续通用换肤时，应改为由皮肤 manifest 声明 `movementBounds` 或 `bodyBounds`，让不同角色可以定义自己的活动边界。

## Phase 0.47 双屏选项

旧版右键菜单中有一个“双屏选项”子菜单：

```text
双屏选项
  单屏
  主屏幕在左侧
  主屏幕在右侧
```

这个入口用于告诉旧版移动逻辑是否允许桌宠从一个屏幕跑到另一个屏幕。Phase 0.47 在 QML 菜单中恢复同名入口，并把状态收口到 `DesktopShellController.screenLayoutMode`：

```text
single       单屏模式，移动边界按当前屏幕夹取
primaryLeft  双屏模式，主屏幕在左侧
primaryRight 双屏模式，主屏幕在右侧
```

当前实现用 Qt 提供的所有屏幕 `geometry()` 合成 `virtualDesktopGeometry()`。在 `primaryLeft` 或 `primaryRight` 模式下，`clampedPetWindowPosition()` 的 X 轴范围使用虚拟桌面宽度，Y 轴仍使用当前屏幕高度。这样桌宠可以横向跨屏移动，同时不会因为上下边界不同而漂出可见区域。

这一步只是恢复旧版“允许跨屏游走”的菜单入口和边界策略，不做完整路线规划。后续移动控制器可以继续扩展：

- 自动判断屏幕排列，不再依赖用户手动选择左右。
- 路径规划时把多个屏幕看成连续可行走区域。
- 在跨屏瞬间根据当前移动方向选择更细的衔接位置。

## Phase 0.48 手型光标

旧版在 `enterEvent()` 中调用：

```cpp
setCursor(Qt::PointingHandCursor);
```

这个细节会在鼠标靠近桌宠时提示用户：桌宠是可以点击、拖拽和互动的。Phase 0.48 在 QML 主 `MouseArea` 上设置 `cursorShape: Qt.PointingHandCursor`，让 v2 继续保留这个轻量交互反馈。

## Phase 0.49 双击释放保护

旧版通过 `clickTimer` 和 `doubleClick` 标志区分单击、双击：

```cpp
if (clickTimer->isActive()) {
    doubleClick = true;
    clickTimer->stop();
}
```

第一次松手只启动 300ms 单击计时。第二次按下如果发生在计时窗口内，就取消这次待定单击，并在第二次松手时执行 `doubleClickEvent()`。这样双击不会先触发一次单击，也不会在双击动作之后再补触发一次单击分区反应。

Phase 0.49 把 QML 的左键流程调整成同样的节奏：`singleClickTimer.running` 代表第一次单击仍在等待确认；第二次按下时设置 `doubleClickPending`，第二次松手时直接调用 `PetRuntime.handleDoubleClick()` 并返回。`MouseArea.onDoubleClicked` 不再承载业务逻辑，避免系统双击信号和松手分支重复触发。

## Phase 0.50 静音音量

旧版“静音”菜单会直接调整同一个 `QSoundEffect` 的音量：

```cpp
soundEffect->setVolume(0);
soundEffect->setVolume(0.8f);
```

Phase 0.15 已经让 `PetRuntime.audioMuted` 阻止新的语音播放请求。Phase 0.50 继续补齐声音组件本身的音量绑定：`SoundEffect.volume` 绑定到 `App.PetRuntime.audioMuted ? 0 : 0.8`。这样用户在一句语音播放到一半时点击静音，也会立即听不到当前语音；取消静音后恢复旧版默认音量。

## Phase 0.52 idle loop 触发配置

旧版站立 GIF 每播完一轮后，会按 70% / 30% 的比例决定是否进入随机待机动作。v2 保留这个节奏，但触发概率和目标候选池已经移动到 Miles 皮肤 manifest：

```json
"behaviorTriggers": {
  "idle.loopFinished": {
    "when": {
      "state": "idle",
      "action": "idle_stand",
      "requiresNoActiveRecipe": true
    },
    "entries": [
      { "type": "pool", "pool": "idle.random", "weight": 70 },
      { "type": "none", "weight": 30 }
    ]
  }
}
```

`PetRuntime.handleIdleLoopFinished()` 只负责接收 QML 发来的“站立循环完成”事件。运行时再根据 `behaviorTriggers.idle.loopFinished` 检查当前状态和权重选择结果。这样 Miles 可以继续接近旧版手感，后续其它皮肤也能把待机节奏改成自己的配置。
