# v1 手感回归与定制化接入

本阶段记录用于 Phase 0.66 – 0.72 期间，跟踪两件事：

1. v1 版本桌宠的功能在 v2 中的迁移现状（已回归 / 临时下掉 / 借 Custom Interaction 回归 / 永久放弃）。
2. 当前 v2 框架代码（`PetRuntime` / `InteractionPipeline` / `HitZoneMatcher` / `PetSurfaceWindow` 等）里混入的 Miles 专属字符串与硬编码常量。

它配合两份设计文档使用：

- 长期 schema 与 Host API 设计：`docs/v2/设计方案/皮肤包播放行为设计.md`。
- 阶段拆分顺序与测试门槛：`docs/v2/设计方案/桌宠运行时职责拆分设计.md` 的 Phase 0.65 – 0.73。

阶段产出的代码细节、commit 记录、回归测试列表仍主要写在 `阶段记录/第0阶段桌面壳验证.md`；本文档专注于"v2 还差什么"和"差的内容如何收口"。

## 2. 框架内残留的 Miles 硬编码点

下面是当前 v2 仓库里把皮肤专属信息写进通用代码的位置，每条都对应一个 Phase 任务。完成对应 Phase 的判定条件之一就是这条目从代码中消失。

| # | 位置 | 问题 | 收口 Phase |
| --- | --- | --- | --- |
| 1 | `apps/desktop/src/pet/interaction/InteractionPipeline.cpp:84` | 睡眠菜单直接发 `recipe("sleep.enterLoopExit")` | 0.68 |
| 2 | `apps/desktop/src/pet/PetRuntime.cpp:90-91` | `sleeping()` 用 `currentActionId == "sleep" && phase == "loop"` 判定 | 0.68 |
| 3 | `apps/desktop/src/pet/PetRuntime.cpp:485` | `acceptsPointerInteraction()` 用 `briefcase_in` 字符串判定 | 0.68 |
| 4 | `apps/desktop/src/pet/PetRuntime.cpp:360-363` | `startStartupSequence()` 直接 `playRecipe("startup.briefcase")` | 0.68 |
| 5 | `apps/desktop/src/pet/PetRuntime.cpp:582-599` | `followUpPoolForCompletedAction()` 写死 walk/run finished 池 | 0.68 |
| 6 | `apps/desktop/src/pet/PetRuntime.cpp:672-687` | `updateFacingFromMovementDirection()` 把 east/west 等映射写死 | 0.68 |
| 7 | `apps/desktop/src/pet/PetRuntime.h:87-88` | `petWindowSize/petImageSize` 写死 `120 * scale / 100 * scale` | 0.69 |
| 8 | `apps/desktop/src/pet/PetRuntime.cpp:313-326,334-358` | `voiceLanguage` 状态和 jp/en/zh 校验、固定 mini/small/medium/big 尺寸 | 0.69 / 0.72 |

## 3. 执行顺序速查

按 `桌宠运行时职责拆分设计.md` 的 Phase 0.65 – 0.73 推进。每个阶段都跟随同名 `check_phase_0_6N_*` 自动检查，并把现状栏目同步更新到本文件第 1 节、第 2 节。

```text
Phase 0.65  架构对齐与门禁：static guardrail + 文档收敛 + dead test 清理
Phase 0.66  ClickBehavior 配置化
Phase 0.67  GestureTracker 拆分
Phase 0.68  rest capability + 启动 / action.completed / 朝向 manifest 化
Phase 0.69  canvas / sizes / surface 收尾
Phase 0.70  CustomInteractionRegistry Host API
Phase 0.71  双击概率 “看招” 借 CI 回归
Phase 0.72  语音 Audio Capability 回归
Phase 0.73  ExpressionMapping schema（Phase 1 收官）
然后进入 Phase 2 接 Go sidecar 与 AI 聊天
```

## 4. 文档维护规则

- 每个 Phase 完成后更新第 1 节"v1 功能现状"和第 2 节"硬编码点"的状态。
- 新发现的 v1 功能或新引入的硬编码项，及时补到本文件。
- 已不需要的条目可以删除，避免历史漂移。
- 长期 schema 与 Host API 接口变更请同步更新 `设计方案/` 下的对应文档；本文不承担长期 schema 职责。
