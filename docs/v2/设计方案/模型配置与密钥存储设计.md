# 模型配置与密钥存储设计

## 背景

v2 桌宠需要连接 LLM API 进行对话。用户需要配置 API Key、Base URL、模型名称等参数。早期实现使用 macOS Keychain 存储 API Key、QSettings 存储其他设置，但存在以下问题：

1. Keychain 的 Data Protection 模式需要 Apple 开发者证书和 entitlements，ad-hoc 签名的开发构建和未签名的发布构建均无法使用
2. 旧代码的 Data Protection / Login Keychain 双路回退逻辑存在 bug（写入走 fallback，读取不走 fallback）
3. 不支持多组模型配置切换
4. 不跨平台（Windows 无 Keychain）

## 设计决策

### 为什么不用 Keychain

- Data Protection Keychain 需要 Apple Developer Program ($99/年) 签发的 provisioning profile，项目为免费开源，不签名发布
- Login Keychain 在未签名 app 每次更新后会弹"允许访问钥匙串"对话框，影响普通用户体验
- 不跨平台

### 为什么用明文 JSON 文件

调研了同类项目：

| 项目 | Stars | API Key 存储方式 |
|------|-------|-----------------|
| Jan (Tauri) | 30k+ | JSON 文件（tauri-plugin-store） |
| Shinsekai (Python/PySide) | 311 | YAML 明文文件 |
| QodeAssist (Qt Creator 插件) | — | QSettings（明文） |
| OpenAI CLI | — | 配置文件 |
| AWS CLI | — | `~/.aws/credentials` 明文 |
| GitHub CLI | — | 默认走系统凭据存储（macOS Keychain / Windows Credential Manager），可选 `--insecure-storage` 明文 |

对于有正式签名的商业软件，系统凭据存储（Keychain / Credential Manager）是更安全的选择。但本项目是未签名的免费开源软件，macOS Keychain 的 Data Protection 模式不可用，Login Keychain 在每次更新后弹授权框。在这种场景下，明文配置文件配合文件权限（macOS 0600 / Windows 用户目录隔离）是务实的体验/维护权衡。Jan、Shinsekai、AWS CLI 等项目采用了同样的策略。

选 JSON 而非 YAML，因为 Qt 内置 `QJsonDocument`，无需引入第三方库。

## 配置文件规格

### 路径

通过 `QStandardPaths::writableLocation(QStandardPaths::AppDataLocation)` 获取：

- macOS: `~/Library/Application Support/MilesEdgeworth/settings.json`
- Windows: `%APPDATA%/MilesEdgeworth/settings.json`

配置文件只放在当前用户目录。macOS 保存后尽量设为仅当前用户可读写。Windows 依赖用户目录隔离，不额外修改 ACL。

### 文件可靠性

- **保存文件：** 使用 `QSaveFile`。先写临时文件，成功后再替换旧文件；写失败时保留旧文件。不启用直接覆盖。
- **文件权限：** 临时文件创建后、写入 API key 前，先设为仅当前用户可读写。保存完成后，对最终文件再设置一次。权限设置失败只记日志，不阻止保存。
- **JSON 解析失败：** 将损坏文件重命名为 `settings.json.bak`，向用户提示"配置文件损坏，已备份为 .bak，请检查或重新配置"。然后以空配置启动。
- **`activeModelConfig` 指向不存在的配置：** 自动 fallback 到 `modelConfigs` 数组的第一个元素。若数组为空，等同于未配置。
- **未知字段：** 读到不认识的字段时先保留。保存时原样写回，避免旧版本删除未来版本新增的字段。
- **配置名称规则：** `name` 不能为空字符串，不能与已有配置重名。UI 层校验。
- **删除当前活跃配置：** 删除后 `activeModelConfig` 自动指向数组中的第一个。若删完所有配置，等同于未配置。
- **重命名配置：** 原地修改 `name` 字段。如果重命名的是 `activeModelConfig`，同步更新。
- **数值字段校验：** `temperature` 可以留空，或填 `0.0–2.0` 的数字。`maxTokens` 可以留空，或填大于 0 的整数。填错时不保存，并在字段旁显示错误。

### 结构

`settings.json` 同时保存模型配置和应用级设置。`modelConfigs` 是数组，顺序由用户决定，UI 下拉框按数组顺序展示。

```json
{
  "activeModelConfig": "deepseek-日常",
  "modelConfigs": [
    {
      "name": "deepseek-日常",
      "baseUrl": "https://api.deepseek.com",
      "apiKey": "sk-xxx",
      "model": "deepseek-v4-flash",
      "temperature": 0.7
    },
    {
      "name": "deepseek-创意",
      "baseUrl": "https://api.deepseek.com",
      "apiKey": "sk-xxx",
      "model": "deepseek-v4-flash",
      "temperature": 1.5,
      "maxTokens": 4096
    },
    {
      "name": "openai-备用",
      "baseUrl": "https://api.openai.com/v1",
      "apiKey": "sk-yyy",
      "model": "gpt-4o"
    }
  ],
  "chat": {
    "msPerChar": 60
  }
}
```

### 字段说明

**modelConfigs 中每个配置：**

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | 是 | 配置名称，用户自定义，用于下拉框显示和 `activeModelConfig` 引用 |
| `baseUrl` | 是 | API 端点地址 |
| `apiKey` | 是 | API 密钥 |
| `model` | 是 | 模型 ID |
| `temperature` | 否 | 采样温度。不填则不传给 API，由模型使用默认值 |
| `maxTokens` | 否 | 最大回复 token 数。不填则不传给 API |

`name`、`baseUrl`、`apiKey`、`model` 四个必填字段缺任何一个，该配置视为无效。

**应用级设置（chat）：**

| 字段 | 说明 |
|------|------|
| `msPerChar` | 文字显示节奏（毫秒/字），与模型无关 |

**注：** 模型的 context window 等固有属性由 Go 侧 `models.Catalog` 从 models.dev 自动获取和缓存，不在此配置文件中。

### 首次启动与未配置状态

文件不存在时，app 正常启动，桌宠照常显示在桌面上。sidecar 正常启动但 provider 为 nil（详见"删除 mock provider 与错误处理"节）。

UI 状态：
- 右上角状态显示"未配置模型"（而非"已连接"——sidecar 在线不等于可用）
- 输入框禁用，placeholder 显示"先点设置填写模型配置"
- 用户在设置页填写第一组模型配置并保存后，文件自动创建，sidecar 重启并连接 API

当前代码的 `enabled: sidecarReady` 需要改为 `enabled: sidecarReady && providerConfigured`，确保 sidecar 启动但未配置时输入框不可用。状态文字也需要区分"未配置"和"已断开"。

### 数据迁移

不做。项目从未发布过，没有历史用户。旧的 QSettings plist 和 Keychain 条目保留不动，不影响新代码。

## 代码架构

### 删除

- `SecretStore.h / .cpp` — 抽象基类
- `MacSecretStore.h / .mm` — macOS Keychain 实现
- `NullSecretStore` — 空实现
- `SettingsService` 中 Keychain 相关逻辑（`ensureApiKeyLoaded`、`m_savedApiKey`、`m_apiKeyLoaded`）
- `MILES_HAS_MAC_SECRET_STORE` 编译宏
- CMakeLists 中对 `Security.framework` 的链接
- Go 侧 `chat.NewMockProvider` 及 mock provider 相关代码

### 新增

`ProviderConfigFile` 类，负责 JSON 文件的读写：

```cpp
class ProviderConfigFile {
public:
    enum class LoadStatus { Ok, FileNotFound, ParseError, PermissionError };

    struct ModelConfig {
        QString name;
        QString baseUrl;
        QString apiKey;
        QString model;
        std::optional<double> temperature;
        std::optional<int> maxTokens;
        QJsonObject extraFields; // 保存暂时不认识的字段
    };

    LoadStatus load();
    bool save();

    QString activeModelConfig() const;
    void setActiveModelConfig(const QString &name);

    QStringList configNames() const;          // 按数组顺序返回
    ModelConfig config(const QString &name) const;
    void setConfig(const QString &name, const ModelConfig &cfg);
    void removeConfig(const QString &name);
    void moveConfig(int fromIndex, int toIndex);

    int msPerChar() const;
    void setMsPerChar(int value);
};
```

### 改造

- `SettingsService`：内部用 `ProviderConfigFile` 替代 `SecretStore` + `QSettings`。`temperature()` / `maxTokens()` 返回值类型从 `double` / `int` 改为 `std::optional<double>` / `std::optional<int>`
- `SettingsController`：适配多配置切换（下拉框选择、新增、删除），打开设置时预填 API Key（masked 显示）
- `ChatController::launchSidecarProcess()`：`temperature` / `maxTokens` 有值时才注入对应环境变量，无值时不注入（当前代码无条件注入，需修改）
- QML 设置页：Temperature / Max Tokens 改为可清空的 TextField，留空表示"不指定"（当前 Slider/SpinBox 无法表达空值）

### Sidecar 环境变量与 Go 侧改动

`temperature` / `maxTokens` 的可选语义需要贯穿整条链路：

| 层 | 当前实现 | 改为 |
|---|---------|------|
| `ProviderConfigFile` | — | `std::optional<double>` / `std::optional<int>` |
| `SettingsService` | 返回固定 `double` / `int`（有默认值） | 透传 `std::optional`，无值返回空 |
| `ChatController` | 总是注入 `MILES_PROVIDER_TEMPERATURE` / `MILES_PROVIDER_MAX_TOKENS` | 有值才注入 |
| `config.FromEnv()` | `float64` / `int` + 默认值 | `*float64` / `*int`，环境变量不存在时为 nil |
| `openai.Provider` | `float64` / `int` 字段 | `*float64` / `*int`，nil 时 JSON `omitempty` 不序列化该字段 |

### 删除 mock provider 与错误处理

Go 侧 `main.go` 中的 `chat.NewMockProvider` 一并删除。未配置时的处理：

- `main.go`：`cfg.Enabled()` 为 false 时，provider 为 nil
- `chatservice.New()` 接受 nil provider
- API handler 收到聊天请求时，检查 provider 是否为 nil，若是则返回 `RUN_ERROR` 事件："未配置模型，请在设置中填写 API Key 和模型信息"
- Qt 侧 `ChatController` 已有 `providerConfigured` 状态，配合 `RUN_ERROR` 向用户显示提示

验收脚本同步：

- `check_phase_2_0_ai_chat_mvp.py`：删除对 `mock_provider.go` 文件和 `mock provider` 事件的检查
- `check_phase_2_1_provider.py`：删除对 `mock-fallback` label 的检查，新增对未配置时 `RUN_ERROR` 错误路径的检查
- `check_phase_2_2_settings.py`：新增对 `ProviderConfigFile` / `settings.json` 的检查

## 设置页 UI

### 布局

- 顶部：模型配置下拉框 + 新增/删除按钮
- 中部：当前选中配置的表单（名称、Base URL、API Key、Model、Temperature、Max Tokens）
- 下方：应用级设置（文字节奏）
- 下方：角色人格（保持不变）
- 底部：打开配置文件目录按钮 + 取消/保存按钮

### 交互

- 切换下拉框 → 表单内容跟着变
- API Key 字段：有值时显示黑点（`echoMode: Password`），加载时预填实际值
- Temperature / Max Tokens：留空表示不指定。旁边放 `(?)` 帮助图标，hover 显示解释
- 打开配置文件目录：调用 `QDesktopServices::openUrl()` 在 Finder / 资源管理器中打开 `settings.json` 所在目录

## 发布流程

### 发布物

| 平台 | 内容 | 格式 |
|------|------|------|
| macOS (Apple Silicon) | MilesEdgeworth.app | .zip 或 .dmg |
| Windows | MilesEdgeworth.exe + Qt 依赖 | .zip（免安装便携版） |

### macOS

1. 构建 Release 版本
2. 将 `.app` 压缩为 `.zip`（或用 `create-dmg` 打包为 `.dmg`）
3. 上传到 GitHub Release

App 未签名。README 中提供安装说明：
> 首次打开：右键点击 app → 选择"打开" → 弹窗中再点"打开"

### Windows

1. 构建 Release 版本
2. 用 `windeployqt` 收集 Qt 依赖 DLL
3. 整个目录压缩为 `.zip`
4. 上传到 GitHub Release

### 签名升级路径

未来如果加入 Apple Developer Program ($99/年)，只需在构建后增加 `codesign` + `notarize` 步骤。配置文件方案不受影响，用户体验升级为正常双击打开。
